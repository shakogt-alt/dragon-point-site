# Phase 3 — Core UI implementation plan

Approved scope: AGENTS.md, CODEX_TASK.md and the user's Phase 3 request.
Base: 344ca0bff9aaba3e3cb6b39d6553e6ede7840ac7.

## Approach

Build the approved editorial Architecture + Data composition in the existing
Next.js locale page. All four dictionaries supply every visible label, brand
string and accessibility name. Shared sections render on the server; Header
alone enhances native disclosures with compact scroll state, Escape/outside
closing and focus restoration. Native disclosures remain usable without JS.

Use approved colors through centralized tokens, existing local fonts, SVG
architecture/diagram artwork without invented market figures. Dark hero and
technology/footer balance the light goal/comparison/process/services sections.
Typography, dividers and structured information carry the design; violet accents
mark CTAs and selected points. Geometry/wordmark components can be replaced later.

## Scope boundaries

- No lead form, endpoint, analytics or KleekTo integration. Advisor/goal CTA
  anchors reach the footer contact placeholder; data-intent attributes reserve
  the three choices for Phase 4 without collecting or submitting anything.
- Comparison is explicitly illustrative and contains qualitative checks, no
  numeric price/return/liquidity assertions. No fake properties/statistics.
- Contact/privacy placeholders are honest inline disclosures, with no dead links
  or empty future SEO pages. Existing SEO configuration/builders remain intact.
- Hebrew shares all components. Logical CSS and source order determine layout;
  only CTA/process arrows mirror, Latin brands/utility icons remain unmirrored.
- Desktop process is six columns flowing right-to-left in Hebrew; mobile process
  is a vertical sequence with down arrows. No page-wide horizontal scrolling.

## Tasks and proof

1. Write landing E2E contracts before UI: sections, one H1, menus/anchors, no form,
   all locales, RTL arrow/layout and all eight widths. Run a targeted case red
   against Phase 2A's existing build. Keep the full SEO suite unchanged.
2. Expand EN/KA/RU/HE dictionaries with localized landing copy, brand labels,
   menus, comparison/process/services/trust/footer copy. Keep SEO metadata stable.
3. Add Logo, Arrow, ArchitectureVisual and action-link primitives; Header/Footer;
   Hero, GoalSelector, BetterDecisions, DragonPointStandard, Services, Technology;
   compose one Landing in the existing locale page. Remove the temporary shell.
4. Apply responsive logical CSS and centralized typography/layout tokens. Test
   mobile menu, language disclosure, Escape, outside click, anchor closing and
   viewport changes. Keep reduced-motion and keyboard behavior immediate.
5. Run lint, format check, typecheck, unit suite, production build and full E2E.
   Run axe on all locale landing pages and open mobile menus. Review screenshots
   EN1440/EN390/KA390/RU1440/HE1440/HE390 plus the full responsive matrix.
6. Obtain independent read-only review; fix substantive findings. Document results,
   pending photography/logo/domain/contacts/editorial inputs. Make a separate
   Phase 3 commit, push and verify remote SHA/report and clean tree. Stop Phase 4.
